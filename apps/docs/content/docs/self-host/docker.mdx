title: Docker
description: Deploy Upstream with Docker Compose.
---

The easiest way to self-host Upstream is with the provided `docker-compose.yml`.

## Compose file

```yml
services:
  app:
    image: ghcr.io/linuskang/up:latest
    build:
      context: .
      dockerfile: Dockerfile
    ports:
      - "3000:3000"
    env_file: .env
    restart: unless-stopped
    depends_on:
      - db
    networks:
      - upstream_net
  db:
    image: postgres:17-alpine
    environment:
      POSTGRES_USER: upstream
      POSTGRES_PASSWORD: upstream
      POSTGRES_DB: upstream
    volumes:
      - upstream_data:/var/lib/postgresql/data
    ports:
      - "5432:5432"
    restart: unless-stopped
    networks:
      - upstream_net
volumes:
  upstream_data:
networks:
  upstream_net:
    driver: bridge
```

## Build locally

If you prefer to build the image yourself instead of pulling `ghcr.io/linuskang/up:latest`:

```bash
docker compose up -d --build
```

## Database migrations

After the containers are running, apply Prisma migrations:

```bash
docker compose exec app npx prisma migrate deploy
```

Migrations must be run every time you update to a new version that changes the schema.

## Updating

Pull the latest image and recreate the container:

```bash
docker compose pull
docker compose up -d
```

Then re-run migrations:

```bash
docker compose exec app npx prisma migrate deploy
```

## Logs

```bash
docker compose logs -f app
```

## Reverse proxy

For production, put Upstream behind a reverse proxy such as Nginx, Caddy, or Traefik. Configure it to:

- Terminate TLS.
- Forward traffic to `http://localhost:3000`.
- Set the `BASE_URL` and `BETTER_AUTH_URL` environment variables to your public HTTPS URL.
