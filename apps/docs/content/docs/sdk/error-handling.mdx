---
title: Error Handling
description: Handle SDK errors and API failures gracefully.
---

The SDK throws an `UpstreamError` when the Upstream API returns a non-2xx response. All other errors are re-thrown as-is.

## UpstreamError

```ts
import { UpstreamError } from '@uplabs/sdk';

try {
  await up.events.ingest({ title: 'Hello' });
} catch (err) {
  if (err instanceof UpstreamError) {
    console.error(`Upstream returned ${err.status}: ${err.message}`);
  } else {
    console.error('Network or unknown error', err);
  }
}
```

## Common status codes

| Status | Meaning |
| ------ | ------- |
| `400`  | Bad request — missing required fields or invalid body. |
| `401`  | Unauthorized — invalid or missing API key. |
| `404`  | Project or user not found. |
| `429`  | Monthly event quota exceeded. |

## Validation errors

A `400` response usually means the payload failed validation. Double-check that:

- `title` is a non-empty string.
- `icon`, if provided, is 32 characters or fewer.
- `actions` contain a valid `variant` and a well-formed URL.
- `data`, if provided, is valid JSON.

## Quota errors

Free plans have a monthly event limit. If you receive a `429` response, wait until the next billing month or upgrade your plan.
